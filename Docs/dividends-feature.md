# Дивиденды, налоги и комиссии — функциональный план

> Статус: **Phase 1 спланирован, реализация не начата.**
> Эпик: [#37](https://github.com/AnnVatlina/InvestPortfolio/issues/37).

---

## Зачем

Приложение сейчас не учитывает доход от дивидендов и связанные с ним расходы — удержанный
брокером налог и комиссии. Цель фичи — добавить их, используя брокерские отчёты Freedom24
(Tradernet).

**Портфель (позиции по акциям)** — отдельная будущая тема, в этот эпик не входит.

Фича разбита на две фазы:

- **Phase 1 — офлайн-импорт отчёта** (этот документ описывает её подробно). Никакой сети,
  никакой авторизации — архитектура остаётся полностью local-only, как и остальное
  приложение.
- **Phase 2 (опционально, позже) — синхронизация по API**, по кнопке, без фона. Требует
  воссоздать auth-слой и Keychain, удалённые при переходе на local-only (см.
  `ARCHITECTURE.md`). Планирование Phase 2 — отдельный тикет
  [#36](https://github.com/AnnVatlina/InvestPortfolio/issues/36), зависит от investigation
  [#32](https://github.com/AnnVatlina/InvestPortfolio/issues/32)/[#33](https://github.com/AnnVatlina/InvestPortfolio/issues/33)/[#35](https://github.com/AnnVatlina/InvestPortfolio/issues/35).
  Не блокирует Phase 1 и не описана ниже в деталях.

---

## Что входит в скоуп Phase 1

- **Дивиденды** — доход по акциям/фондам.
- **Налоги** — удержанный брокером налог (расход).
- **Комиссии** — брокерские комиссии за сделки (расход).
- Импорт отчёта Freedom24 (`.xlsx`) как единственный способ получить данные.
- Повторный импорт того же или перекрывающегося по периоду отчёта — без дублей.
- Удаление всех импортированных операций.

## Что не входит в Phase 1

- **Ручное добавление операций — временно запрещено.** Осознанное и обратимое
  ограничение: единственный способ получить данные в Phase 1 — импорт отчёта. Если позже
  понадобится ручной ввод, это отдельный тикет.
- Синхронизация по API, авторизация, Keychain — Phase 2.
- Портфель/позиции по акциям — отдельный будущий эпик.
- Поддержка брокеров кроме Freedom24/Tradernet.
- Поддержка CSV-варианта отчёта — проверили, пользователь экспортирует именно `.xlsx`,
  других форматов не рассматриваем.

## Формат отчёта Freedom24 (`.xlsx`)

Разобран на реальном примере (`tradernet_table-2.xlsx`) без сторонних библиотек — `.xlsx`
это zip-архив с XML внутри (`xl/sharedStrings.xml` + `xl/worksheets/sheet1.xml`).

Один лист, 6 колонок, первая строка — заголовок:

| Колонка | Пример | Заметки |
|---|---|---|
| **Операция №** | `125392993` | Уникальный числовой ID операции. **Ключ дедупликации** — не нужны эвристики по дате/сумме/тикеру. |
| **Дата** | `46301.49290509259` | Excel serial number, эпоха 1899-12-30, с временем суток (дробная часть). |
| **Операция** | `Дивиденды`, `Налоги`, `` Комиссия за сделки `` | Строка с лишними пробелами по краям у "Комиссия за сделки" — нужен `trim`. Возможны другие типы в других отчётах — **не терять их молча**, маппить в `.other` с сохранением исходной строки. |
| **Комментарий** | `Dividends on security (...(VCIT.US)), record date 2026-10-01. Per security 0.3398 USD...` | Свободный текст. Тикер можно парсить регуляркой, но формат не гарантирован — тикер опционален, не блокирует импорт при неудаче парсинга. |
| **Сумма** | `7.14` / `-2.14` | Уже со знаком: налоги и комиссии — отрицательные. |
| **Валюта** | `USD` | — |

Детали разбора и ход исследования — в закрытом тикете
[#34](https://github.com/AnnVatlina/InvestPortfolio/issues/34).

### Известное ограничение: извлечение тикера

`BrokerOperation.ticker` парсится из «Комментария» регуляркой (токен вида
`БУКВЫ.СУФФИКС`, суффикс 1–5 заглавных букв — например `VCIT.US`, `SBER.ME`, `FOO.L`).
Это эвристика, проверенная только на единственном реальном отчёте (все позиции — рынок
США, суффикс `.US`). Паттерн **не завязан жёстко на `.US`** — других суффиксов такой же
длины он тоже поймает, — но если в отчёте встретится бумага без тикера в комментарии
вообще или с принципиально другим форматом (например, без суффикса после точки), `ticker`
останется `nil`. Это не ошибка импорта — поле всегда опционально и ни на что не
блокирует. Если при реальном использовании появятся комментарии, где тикер не
распознаётся, паттерн нужно будет расширить по факту новых примеров, а не гадать заранее.

## Идемпотентный импорт (без дублей)

«Операция №» — внешний уникальный ID из отчёта Freedom24. При импорте сервис сравнивает
номера операций из файла с уже сохранёнными (`existingOperationNumbers()`) и добавляет
только новые. Повторная загрузка того же файла добавляет 0 новых записей; загрузка файла
за более широкий период добавляет только операции, которых не было раньше.

## Экраны Phase 1

- **Вкладка «Дивиденды»** (новая, в `MainTabView`) — список операций, группировка по
  месяцам, итоги по типу (дивиденды/налоги/комиссии) и валюте.
- **Пустое состояние** — только кнопка «Импортировать отчёт». **Без** кнопки «+
  Добавить» (ручной ввод запрещён).
- **Импорт отчёта** — файл-пикер (`.xlsx`) → парсинг → сохранение новых операций → сводка
  результата (сколько добавлено / сколько пропущено как дубликаты / ошибки парсинга).
- **Удалить все** — деструктивное действие с подтверждающим алертом.
- Никакой формы создания/редактирования операции в этой вкладке не существует.

Интеграция в «Аналитику» (дивиденды как доход, налоги+комиссии как расход на существующих
графиках `AnalyticsViewModel`) — опциональный тикет
[#42](https://github.com/AnnVatlina/InvestPortfolio/issues/42), не блокирует MVP вкладки.

## Архитектурные слои Phase 1

- **ZIPFoundation** (SPM) — первая сторонняя зависимость в проекте, только для
  распаковки `.xlsx`. XML внутри парсится встроенным `XMLParser` — своего кода немного.
- `DividendReportParser` — `parse(fileURL:) throws -> [ParsedBrokerOperation]`. См.
  [#38](https://github.com/AnnVatlina/InvestPortfolio/issues/38).
- `BrokerOperation` (SwiftData `@Model`) + `BrokerOperationType` enum (`dividend`, `tax`,
  `commission`, `other`) + `BrokerOperationsRepository` (протокол + SwiftData + InMemory,
  по текущему паттерну репозиториев). См.
  [#39](https://github.com/AnnVatlina/InvestPortfolio/issues/39).
- `DividendsService` — импорт с дедупликацией, `deleteAll()`, группировка для UI. См.
  [#40](https://github.com/AnnVatlina/InvestPortfolio/issues/40).
- `DividendsViewModel`, `DividendsView`. См.
  [#41](https://github.com/AnnVatlina/InvestPortfolio/issues/41).

Никакой сети, Keychain или auth-слоя в Phase 1 не требуется — в отличие от более раннего
черновика этого документа, который предполагал обязательную синхронизацию по API с самого
начала.

## История решений

- Исходный черновик предполагал обязательную синхронизацию по API с самого начала —
  решено начать с офлайн-импорта отчёта (Phase 1), синхронизацию по API отложить в
  Phase 2 и сделать её опциональной надстройкой, а не обязательной частью.
- Налоги и комиссии изначально были упущены и добавлены по итогам обсуждения — они тоже
  присутствуют в брокерских отчётах и трекаются как расход, а не только дивиденды как
  доход.
- Ручное добавление операций временно запрещено в Phase 1 — единственный источник данных
  на этом этапе — импорт отчёта.
- Формат отчёта — `.xlsx` (проверено, CSV-варианта экспорта в личном кабинете нет/не
  используется), парсинг — через новую зависимость ZIPFoundation + встроенный `XMLParser`
  (первая сторонняя зависимость в проекте).
- Дедупликация при повторном импорте — по уникальному «Операция №» из отчёта, а не по
  составному ключу (тикер+дата+сумма).
